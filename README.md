# 創作アイデアガチャ

世界観・関係性・葛藤を組み合わせて、物語のタネを引く創作支援ツールです。

[公開サイト](https://nyuriwossan.github.io/creative-idea-gacha/)

## 使い方

1. 舞台・トーン・用途を選び、必要なら「好みで絞る」で方向を最大3つ選びます。「固定していない項目を引く」でタネを引きます。設定変更だけでは今の素材は変わりません。
2. 残したい項目を固定します。「編集」で自分の文を反映すると自動で固定します。
3. 必要なときだけ「人物を足す」「物語を動かす」「質問で深める」を開きます。
4. 保存名やメモを付けて保存します。読み込んだ作品は「上書き保存」と「別名で保存」を選べます。
5. JSONでバックアップし、Markdownで作品づくりのメモに持ち出せます。

基本7項目・944素材・7用途・5トーン・16テーマ（最大3つ）、人物6項目、進行4項目、4区分の質問を使えます。履歴はセッション内の最大20スナップショットです。

編集欄の「反映」を個別に押さなくても、保存・コピー・現在JSON・Markdown出力時に、本文・短語・背景チェック・質問回答・人物名・保存名・タグ・メモをまとめて反映します。入力に問題があれば全体を止め、該当欄へ移動します。入力は残るので、直してから同じ操作を行ってください。個別の反映・取消も使えます。

## 素材の組み合わせ方

新規利用の「まとまり重視」は世界観や固定素材から最大2つの題材を選び、関係・事件・葛藤・ひねりに関連する候補の重みを高めます。「自由に混ぜる」は追加の題材・構造による重みを使わず、意外な組み合わせを残します。どちらも舞台・背景・トーン・固定・テーマ優先枠を守り、設定を変えるだけでは引き直しません。旧保存は従来に近い「自由に混ぜる」で読み込みます。

第3回改修では葛藤40・ひねり40（対応30組）、日常の世界観・ジャンル・関係・事件・ギミック28件、トーン5対応ジャンル6件、結末12・代償6件を追加しました。既存基本300件に題材タグ、既存の葛藤・ひねり77件に構造リンクも補っています。自動で物語の因果や意味の整合性を保証する機能ではありません。

## 世界観を広げる4テーマ

| テーマ | 育てられる方向 | 基本の新規素材 |
|---|---|---:|
| 獣人・人外社会 | 身体や文化の違い、共存の制度、交流 | 80 |
| 砂漠・王国・宮廷 | 水利、交易、隊商、宮廷の利害 | 80 |
| 恋愛ファンタジー・契約恋愛 | 契約と本心、関係を選び直す自由 | 70 |
| 日常ファンタジー・店と共同生活 | 生活魔法、仕事、住人の小さな協力 | 70 |

既存12テーマと組み合わせられます。条件に合う素材が十分ある全部抽選では、基本7項目のうち3カテゴリ以上と、関係・事件・葛藤・ギミック・ひねりのうち2カテゴリ以上へテーマを反映します。選んだテーマはOR型で扱い、使える候補がある場合は全選択テーマが結果に現れるよう配慮します。優先するカテゴリは毎回変わります。

世界観が明示する「獣人・砂漠・移動生活・オアシス・王族や宮廷・交易・魔法・精霊」の8背景を確認してから、必要条件を持つ素材を引きます。テーマ選択だけで獣人や魔法の存在を決めません。手入力の世界では「この世界にある要素」を自分で指定できます。元の候補の背景は自動で引き継ぎません。固定やトーン、背景で関連素材が不足すると理由を表示し、使える素材から抽選します。

人物は各項目40候補、進行の期限・障害は各36候補、代償42候補、結末48候補、質問は各区分23件です。第2回で共有人物60件、進行64件、質問32件を追加し、第3回で代償・結末を拡張しました。人物の立場・目的・秘密は主人公と相手役で定義を共有し、人物別のIDで区別します。

舞台やテーマは抽選の相性を考慮するための情報です。物語の因果関係や設定の整合性を自動で保証する機能はありません。「設定を確かめる質問」は創作者が考えるための一般的な問いです。

## 保存と旧データ

「保存済み作品すべてをJSON保存」は保存済み一覧のバックアップです。現在の未保存編集は含みません。現在のタネは個別JSONで持ち出せます。最後の書き出し操作時刻と、その後の保存内容の変更を表示し、5回の変更でバックアップを案内します。端末に実際にファイルを保管できたかは確認できません。現在JSONとMarkdownではこの時刻を更新しません。

- 保存先は同じブラウザ・同じサイトのlocalStorageです。クラウドには送信しません。
- 新領域は `creativeIdeaGacha_v2`。作業中の状態と保存作品をひとつの領域に保管します。
- 旧領域 `creativeIdeaGacha_state` / `creativeIdeaGacha_savedItems` は削除しません。
- 初回移行では `creativeIdeaGacha_legacyBackup` に元JSONを保管し、新領域への書き込みが成功してから移行完了とします。候補から削除された旧文面・生成済み文章・固定・ID・日付・お気に入りも保持します。
- 壊れたデータや未来バージョンがある場合は、書き込みを止めて知らせます。「元データを取り出す」で保管できます。
- 容量不足では保存成功の表示を出しません。現在の作業内容はメモリに残し、JSONで取り出せます。
- インポートは検証・プレビュー後の追加のみです。IDが衝突する作品には新しいIDを付けます。最大5MiB・500件です。
- schemaVersion 2を維持し、背景・必須条件もJSONに保存します。旧v2に背景がない場合、定義に残る生成素材だけを候補IDで補います。保存本文・短語・要約・タイトル・固定は変更しません。手入力や消失した候補には背景を推測しません。未知の背景IDは必要条件を満たしません。

ブラウザのデータを消すと保存も失われるため、JSONを定期的に保管してください。履歴で保存一覧の削除や取り込みを取り消すことはできません。

## 開発・検証

ビルド・フレームワーク・APIキーは不要です。ES Modulesを使うため、ローカルで確認する場合はHTTPサーバーを使います。

```sh
python -m http.server 8000
```

`http://localhost:8000/` を開きます。GitHub Pagesではmainブランチのルートを公開します。すべてのアセット参照は相対パスです。

Node.js 24で自動検証します。依存パッケージのインストールは不要です。

```sh
node --test tests/*.test.js
# 子プロセスが制限される環境
node --test --test-isolation=none tests/*.test.js
```

候補量・トーンと舞台・テーマ重みと優先枠・背景条件・固定・履歴・出力・質問保護・保存ID・データ移行・JSON・容量不足に加え、一括編集・抽選方針・バックアップを検証します。今回再実行した自動テスト49件、ブラウザ確認42項目の結果と、同じ設定で両方針を比べた3組の実例は [検証レポート](./VALIDATION.md) にあります。スマートフォン相当の表示・入力イベントで確認し、実機iPhone／Safariは未検証です。

ブラウザ検証は開発時だけPlaywrightを利用します。配信ファイルに依存パッケージは不要です。

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node tests/browser-check.cjs
```

Chromeを使う場合は `BROWSER_CHANNEL=chrome`、成果物の保存先を変える場合は `TEST_OUTPUT_DIR` を環境変数で指定できます。

## ファイル

- `js/base-data.js` / `js/data.js`：既存候補・追加候補・設定・メタデータ
- `js/theme-pack-*.js` / `js/pack-definition.js`：新しい4テーマの基本・人物・進行・質問の定義
- `js/context.js` / `js/priority.js`：背景要素・既存定義の補完・テーマ優先枠
- `js/extra-data.js` / `js/questions.js`：人物・進行・質問
- `js/core.js`：抽選・編集・履歴・用途別出力・Markdown
- `js/storage.js`：検証・旧データ移行・保存・JSON入出力
- `js/drafts.js` / `js/backup.js`：編集の一括検証・反映、バックアップ操作の案内
- `js/cohesion.js`：題材と構造による抽選の重み
- `js/story-data.js` / `js/story-metadata.js`：第3回の新規素材、既存IDへの明示的な題材・構造補完
- `js/app.js` / `style.css` / `index.html`：画面と操作

外部AIによる生成・クラウド・相関図・共有URLは今回の対象外です。
